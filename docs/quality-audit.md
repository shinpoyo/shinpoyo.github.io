# サイトの品質チェック（2026-10-25）

AdSense の審査で「有用性の低いコンテンツ」と判断されたため、全ページを点検した結果と、直す順番をまとめる。

- 対象：サイト内の 20 ページ（SMUDGE のゲーム本体は除く）と、ゲーム本体 6 本の見え方
- 方法：本文の文字数・見出し・画像・表・FAQ を機械的に数え、内容は人の目で「このサイトにしかない情報か」を判定した
- 注意：Google は具体的な基準も、どのページが原因かも公表していない。ここに書いた「判定」と「原因」は推測

## 結論

- **技術面に問題はない**：`robots.txt`・`sitemap.xml`・`ads.txt` は取得でき、`noindex` はなく、タイトル・説明文の重複もない。構造化データも付いている
- **弱いのは「中身」**：この 2 週間で 8 本の記事を急いで増やしたが、半分は「どこにでもある解説」で、このサイトにしかない情報（自分の体験・実際のデータ・実際の画面）が少ない
- **運営者の情報が薄い**：About が約 770 字で、誰が何を作っているのかが伝わりにくい
- **ゲーム本体のページは、検索エンジンには空に近く見える**（JavaScript で描くため）。サイトの評価は、紹介ページと記事に頼ることになる

## ゲーム本体の見え方（検索エンジンから）

生の HTML に含まれる本文の量。ゲームは JavaScript で画面を作るため、ほとんど空に見える。

| ゲーム | 本文 | 補足 |
|---|---|---|
| `/mashimashida/` `/smudge/` `/Bullet-Reflector/` | 0 字 | タイトルと説明文のみ |
| `/keshikasu/` | 20 字 | 同上 |
| `/Reversi-with-Sis/` | 263 字 | **説明文（description）がない** |
| `/haru_nechan_quiz_app/` | 578 字 | |

これらは今、サイトマップに入っている。「中身が空のページ」を検索エンジンに大量に見せる形になっているため、**サイトマップからは外し、紹介ページだけを載せる**案を検討したい（影響は小さく、元に戻せる）。ゲーム側の説明文は、各リポジトリで足せる。

## 直す順番

効果の大きそうな順。

1. **運営者ページ（About）に、自分のことを書く**【要・本人の情報】
   名前の由来、作り始めたきっかけ、作った作品、使っている技術など。書ける範囲で十分。
2. **体験を軸にした記事を足す**【要・本人の話】
   「ねーちゃんとオセロ」の型（実話＋仕組み）が強い。マシマシ打、けしカス、SMUDGE、はるしねーちゃんにも、きっかけや失敗談があるはず。
3. **どこにでもある記事は、厚くするか、まとめる**
   - `romaji-n` と `romaji-tricky` は、1 本の「ローマ字入力ガイド」にまとめ、ゲームで実際につまずきやすい言葉の例や画面を足す
   - `typing-practice` は、自分の練習の体験や、ゲームの記録の見方を足す
   - `ai-hallucination` は、はるしねーちゃんの問題作りの経験を足す
4. **画像・画面を足す**
   画像のない記事に、実際の画面や図を入れる。キーやアカウント情報が写らないよう注意する。
5. **作品ページを厚くする**
   SMUDGE と けしカス から。画面と、遊んでみて分かったことを足す。
6. **ページ上で動く「道具」を付ける**
   例：Web Audio の記事に「音を鳴らすボタン」、ローマ字の記事に「打ち方の確認ボックス」。他のサイトにない価値になる。
7. **サイトマップを整理する**（上の案）
8. **更新のペースを保つ**
   一気に増やすより、週に 1〜2 本を続ける。更新日が並ぶことが「手入れされている」ことの目安になる。
9. **実際に遊ぶ人を増やす**
   サイトの外の作業（SNS での紹介など）。審査は、実際の利用があるかも見ている。

## 再審査のタイミング

上の 1〜3 が終わり、新しい内容が検索に登録されてから（目安：数週間後）。Google は「サイトを再送信する前に確認する点」として、品質・手入れ・ユーザーの関心の 3 つを挙げている。すぐに何度も再送信しても効果は薄いと思われる。
