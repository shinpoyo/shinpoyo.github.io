# Search Console の確認手順

「サイトが検索に登録されているか」を確かめる手順。AdSense の再審査の前に、いちど見ておく。
Claude は Search Console を見られないので、見た結果を Claude に伝えてもらう。

- 開く：https://search.google.com/search-console/ → プロパティ `shinpoyo.com`（所有権は DNS の TXT で確認済み）

## 1. サイトマップが読み込めているか

左メニュー **インデックス作成 → サイトマップ**

- 送信済みの `https://shinpoyo.com/sitemap.xml` の「ステータス」を見る
  - **成功しました**：問題なし。「発見された URL」の数が、いまのサイトマップの数（26 件前後）に近いか確認
  - **読み込めませんでした**（10/12 に出ていた表示）：登録直後によく出る。いまも出ているなら、いったん削除して、`sitemap.xml` と入れて送り直す。それでも出る場合は、画面のエラーの文面を Claude に伝える
- サイトマップ自体は、`https://shinpoyo.com/sitemap.xml` で取得できることを確認済み（200・XML）

## 2. 何ページが登録されているか（いちばん大事）

左メニュー **インデックス作成 → ページ**

- 上のグラフの「登録済み」「未登録」の数を見る
- 下の「ページがインデックスに登録されなかった理由」の一覧を見る。特に次の 2 つが大事
  - **クロール済み - インデックス未登録**：Google はページを見たが、登録しなかった。**中身の評価が低い可能性が高い**。ページの URL と数を控える
  - **検出 - インデックス未登録**：まだ見に来ていないだけのことが多い。時間が経てば減る
- 「登録済み」をクリックして、どのページが入っているかも見る（紹介ページ・記事が入っているか）

Claude に伝えてほしいこと：登録済みの数、未登録の数、未登録の理由とその数、可能なら「クロール済み - インデックス未登録」のページ名。

## 3. 個別のページを調べる

上の検索欄に URL を貼る（**URL 検査**）。確認するページの例：

- `https://shinpoyo.com/`
- `https://shinpoyo.com/articles/making-sis-othello/`
- `https://shinpoyo.com/works/reversi-with-sis/`

見るところ：「URL は Google に登録されています」か。登録されていなければ、理由と、「ライブテスト」で取得できるか。
登録されていないページは **インデックス登録をリクエスト** を押せる（1 日に押せる回数に上限あり。大量には使えない）。

## 4. 検索結果での見え方

左メニュー **検索パフォーマンス**

- 「合計クリック数」「合計表示回数」を見る。サイトを公開して 2 週間では、少ないのがふつう
- 「ページ」タブで、表示されているページを見る（どの記事が検索に出ているか）
- 「クエリ」タブで、どんな言葉で出ているか見る。次に書く記事のヒントになる

## 5. 問題が出ていないか

- **セキュリティと手動による対策 → 手動による対策**：「問題は検出されていません」ならよい
- **セキュリティと手動による対策 → セキュリティの問題**：同上
- **エクスペリエンス**（表示速度・モバイルでの使いやすさ）：エラーがなければよい

## 6. 構造化データの確認（任意）

https://search.google.com/test/rich-results に記事の URL を入れる。「BlogPosting」「パンくずリスト」が検出されればよい。

## 結果の読み方

| 状況 | 意味 | 次にやること |
|---|---|---|
| 登録済みがほとんど | 検索には登録されている。審査の原因は「中身の評価」の可能性 | [品質チェック](quality-audit.md) の順に直す |
| 「クロール済み - インデックス未登録」が多い | Google が見たうえで登録しなかったページがある | そのページを厚くする、またはまとめる |
| 「検出 - インデックス未登録」が多い／登録済みが少ない | まだ見に来ていない | 待つ。URL 検査でリクエストを出す。サイトの外から紹介リンクを増やす |
| サイトマップがエラーのまま | 取得に問題がある | エラーの文面を Claude に伝える |
